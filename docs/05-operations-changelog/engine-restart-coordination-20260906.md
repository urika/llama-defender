# 引擎重启协调协议

> 设立：2026-09-06
> 起因：P1a.3 Gate A 验证期间连续 4 次后端强制重启（stop-backend 优雅停止超时 → kill），
> 期间并行会话实验在跑；重启后出现 **8,056 次 POST /v1/chat/completions 404 紧循环重试**
>（疑似被重启打断的客户端残骸，归属未查明）。
> 前提：多会话共享单引擎（--max-num-seqs 1，Metal 活跃 25-29GB）——
> **一次重启 = 杀掉所有会话的在途请求 + 清空全部 KV 缓存条目**。

## 硬规则

1. **冻结窗口**——以下任一情况成立时，禁止 `stop-backend` / `restart-backend` / `restart`：
   - swe-eval/批跑进程存活（`run_agent`）
   - 引擎日志最近 10 分钟内有推理事件（`[schedule]` / `[REQUEST] POST` / `[cache_fetch]`）
   - 用户已告知的实验/批跑进行中
2. **重启前三查**（全部通过才动手）：
   ```bash
   # ① 批跑进程
   ps -ef | grep run_agent | grep -v grep
   # ② 引擎最近推理（有输出 = 冻结中）
   tail -200 logs/llama-server.log | grep "\[schedule\]" | tail -3
   # ③ 代理状态与会话
   curl -s http://127.0.0.1:4000/api/status | python3 -m json.tool | head -12
   ```
3. **公告先行**：重启意图告知用户/共享通道，获确认后执行。多 AI 会话并行工作
   是本仓库常态——「我没看见有人在跑」不构成豁免，三查是下限。
4. **紧急例外**：真 OOM（Metal 越限且推理持续失败）/ 进程挂死无响应——
   允许先斩后奏，**事后必须在本文件 changelog 登记**。
5. **重启后检查**：观察引擎日志数分钟——出现连续 4xx 紧循环 = 有客户端被打断，
   找到主人协调（可按源端口瞬时连接 `lsof -iTCP:8081` 采样，或询问并行会话）。
6. **自有流量豁免**：会话对自己当轮创建、确认无他人共享的任务重启不需公告；
   共享引擎上有他人流量时一律走 1-3。

## 给 AI 会话的特别说明

本仓库常有多个人/AI 会话并行工作，引擎是被共享的单例资源。你在 CLAUDE.md
看到的只是硬规则；判断「现在能不能重启」永远以三查的**实际输出**为准，
不以「我上次看的时候没流量」的记忆为准。

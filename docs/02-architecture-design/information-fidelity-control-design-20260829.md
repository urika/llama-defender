# 信息保真控制（IFC）设计：控制论 × 信息论框架下的上下文管理重读与闭环方案

> **状态**：设计提案（未实施）｜**日期**：2026-08-29
> **来源**：对 MMPO/信念熵综述（`~/APP/mem_sys/my_wiki/.../mmpo-belief-entropy-review.md`）的两轮分析结论——①可借鉴的是"把不可观测的上下文质量变成可观测信号"的度量思想而非 RL 训练方法；②环节吻合度核对：观测面高度吻合、控制面部分同构、优化面完全开环。
> **一句话**：本系统所有自动控制回路都作用在**体量信号**（token 预算、重复计数、性能衰减）上，没有一条作用在**信息信号**上；IFC 用三层传感器 + 台账对账式信念审计 + 事件门控执行器，把这个唯一开环的"信息环"补成可度量、可验证、可门控的闭环——不训练、不动后端、不违反 append-only。

---

## 0. 设计原则（约束前置）

继承仓库既有方法论，本设计受五条硬约束：

1. **观测先行**：先度量后控制（R13-R16 DIAG 数据面先例），控制逻辑必须有离线验证的信号效度才允许接入。
2. **事件触发**：探针只在信息损失事件（ILE）发生时执行，成本有界；不做每轮探针。
3. **默认关**：所有新控制项 reloadable + 默认关闭；Tier-0 被动度量可默认开（零成本纯派生）。
4. **stdlib only**：新模块不引入第三方包；探针走既有 urllib 分发路径。
5. **append-only 不可侵犯**：探针是侧路请求，永不进入 canonical 历史、永不写台账 action、永不扰动 prefix。

## 1. 控制论重读：回路盘点

### 1.1 控制要素映射

| 控制论要素 | 系统对应物 |
|---|---|
| 被控对象（plant） | backend 生成过程 × 任务环境（repo / tools） |
| 传感器 | token 计数、`hit_ratio`、`drop_ratio`、timings、loop 检测器、台账（R14）、sent_view 档案（R15） |
| 执行器 | 压缩器、截断器、路由器、DynamicMaxTokens、队列、循环干预注入、watchdog |
| 设定值 | `PROXY_OOM_SAFE_TOKENS`、`PROXY_CTX_KEEP_MESSAGES`、target ratio、loop 阈值 |
| 扰动 | 客户端上下文增长、Metal 内存压力、模型缺陷（rapid-mlx 忽略 max_tokens）、云端失败、**任务信息隐性丢失**（新识别） |

### 1.2 回路清单：三类回路，信息环是唯一开环

| 回路类 | 回路 | 传感器信号 | 状态 |
|---|---|---|---|
| **基础设施环**（自动闭环） | OOM Safety FIFO（stage 17） | token 预算 | ✅ 闭环 |
| | DynamicMaxTokens（stage 2） | lifecycle 档位 | ✅ 闭环 |
| | stream idle watchdog / 队列超时 | 空闲时间 / 等待时间 | ✅ 闭环 |
| | 熔断 + 冷却 + fallback chain | HTTP 错误 | ✅ 闭环 |
| | watchdog 后端重启 | 性能衰减 | ✅ 闭环 |
| **行为表面环**（自动闭环） | tool/text loop 干预（8/9/11） | bigram 相似度、去重哈希 | ✅ 闭环 |
| | blocker 检测（4）、reread 注入（12） | 异常模式、重读目标 | ✅ 闭环 |
| **信息环**（**开环，人闭合**） | 压缩质量 | 仅 `compression.ratio`（过程量，非保真度量） | ❌ 开环 |
| | 截断质量 | DEF-107 摘要注入（无信号启发式补偿） | ❌ 开环 |
| | 信念漂移 | `canonical_mismatch` 只测不控 | ❌ 开环 |
| | 压缩/截断参数自适应 | 无（静态 profile + 人肉 reload） | ❌ 缺环 |

**Ashby 必要品种定律视角**：扰动空间里有"任务信息隐性丢失"这一类扰动（症状：漫无目的重读、动机-结果断裂、会话晚期衰竭），但执行器品种里没有任何一个能对它做出**定向**响应（现有品种全部是"压得更狠/丢得更多"方向）。品种缺口是结构性的：**只有减法执行器，没有保真执行器**。

### 1.3 控制层级（映射到现有 stage）

```
L4 治理层（人，慢）     config / reload / 文档 / 本设计文档本身
L3 监督层（慢，会话级） LifecycleClassifier(1) / ContextEngine epoch(0.5) / profile 选择   ← IFC 门控接入点
L2 调节层（快，请求级） 压缩(7)/截断(14)/路由(2.5)/输出预算(2)/队列/循环干预(11)        ← IFC 传感器挂载点
L1 观测层             DIAG 数据面(R13-R16) + Tier-0 结构指标 + 信念探针（本设计新增）
L0 被控对象           backend 生成 × 任务环境
```

监督层给调节层下设定值、调节层快速抑制偏差、观测层同时服务两层——这与现有 stage 编号天然对齐，**不需要重排管线**。

## 2. 信息论重读：损失链模型

### 2.1 信道链与损失点

```
S(任务状态,隐) ──环境写入──> H(客户端全量历史) ──管线有损变换──> V_t(sent_view)
                              ▲                                        │
                              │ 不可逆回写(动作通道)                    ▼ 后端推理
                              └────────── A_t(动作) ←── B_t(模型信念 P(S|V_t)) 
```

两条定理级约束：

- **数据处理不等式（DPI）**：`I(S; B_t) ≤ I(S; V_t) ≤ I(S; H)`。管线任何 stage 都不能创造任务信息，只能在"哪里损失、损失多少"上做分配。**压缩设计的正确表述不是"消除损失"而是 rate-distortion 分配：在 token 预算下最大化任务相关信息保留**。BM25 是逐点相关性启发式，TS-4 类型感知是结构启发式，信息钉（§4.3）是显式高价值配额——三者是同一目标下逐步 explicit 化的近似。
- **Good Regulator 定理**（Conant-Ashby）：好的调节器必须包含被调系统的模型。canonical session（append-only）+ 台账（R14）正是代理层对会话的"内部模型"——这为 ContextEngine 的设计方向提供理论背书：它不只是 prefix cache 优化，它是调节器成立的前提。

### 2.2 本系统真实的损失点（前两轮核对结论）

| 损失通道 | 文档（MMPO 综述）假设 | 本系统实际 | 结论 |
|---|---|---|---|
| 链式摘要噪声累积 | 主病灶（MemAgent 覆写） | 默认路径无状态逐请求重算，无链式结构 | **结构性排除** |
| LLM 摘要幻觉注入 | 噪声来源之一 | ctx_engine 折叠为确定性抽取（`_round_summary` "确定性无 LLM"） | **结构性排除**（代价是更高信息损失） |
| **V_t 构造损失** | — | 压缩 drop / fifo 截断 / epoch 折叠 | **真实损失点 1：可度量、可门控（IFC 主对象）** |
| **动作不可逆回写** | 隐含于信念偏差 | 有损视图下的动作（编辑/调用）永久进入历史；fifo 丢动机留结果——"见效果不见原因" | **真实损失点 2：只能预防（门控损失点 1）+ 行为检测（§4.4）** |

损失点 2 是控制论意义上的**结构性偏差**：被控对象状态（历史）由运行在降级估计上的控制器输出所更新，误差在写入时刻不可见且永久化。这解释了为什么 DEF-107 的截断摘要注入有效方向正确但无信号——它在补偿一个从未被测量过的损失。

## 3. 概念定义（系统信息论词汇表）

| 概念 | 符号 | 定义 | 可观测性 | 系统对应物 |
|---|---|---|---|---|
| 任务状态 | `S` | 隐变量：目标、约束、repo 真实状态 | 不可观测 | — |
| 客户端历史 | `H` | 客户端每轮重发的全量原始消息 | 可观测 | 请求体 |
| 发送视图 | `V_t` | 第 t 轮实际送入后端的消息 | **已观测** | sent_view 档案（R15） |
| 模型信念 | `B_t = P(S\|V_t)` | 后端条件于视图的任务状态估计 | 间接（探针/行为） | — |
| 视图保真度 | `F = I(S; V_t)` | 视图与任务状态的互信息 | 不可直接测 → 分层代理 | 本设计核心被控量 |
| 信念熵 | `H_BE(V_t)` | MMPO 借鉴：锚定问题下响应分布的熵（清晰记忆→低熵） | 探针可测 | §4.1 Tier-1/2 |
| **台账对账偏差** | `D_ledger` | 探针答案与台账 ground truth 的可验证差（recall/F1 口径） | **可测** | §4.1 对账审计（本设计关键增量） |
| 信息损失事件 | `ILE` | 压缩 drop / 截断 drop / epoch 折叠发生的请求轮 | 可观测 | §4.2 账本标记 |
| 信息钉 | `Pin` | 跨 ILE 必须存活的最高价值内容（任务陈述/最新目标/错误签名/被截断决策） | 可观测 | §4.3 |
| 游走状态 | `W` | 高熵端衰竭：动作多样性高 + 重读压力高 + 台账无新句柄 | 可观测（Tier-0 组合） | §4.4 |

**`D_ledger` 相对 MMPO 的关键差异化**：MMPO 的开放问题（综述 §6.1）是锚定问题效度无法保证——熵低只说明模型"自认为清楚"（锐度），不说明信念正确（校准），一致地错是熵探针的盲区。但 coding agent 场景下 **R14 台账就是 ground truth**：把锚定问题半抽取化（"列出已改动文件"），答案可与台账 materials 对账，把"信念锐度代理"升级为"信念准确性度量"。这是本系统相对通用 MMPO 框架的结构优势：**信念偏差第一次变成可对账量，而非纯熵代理**。

## 4. 算法设计

### 4.1 传感器：三层信号

#### Tier 0：结构指标（零成本，纯既有数据派生，Phase 0 即落地）

| 指标 | 公式（初版） | 含义 |
|---|---|---|
| 保留率 | `R_t = 1 − dropped_chars_t / \|V_{t−1}\|`（dropped = 各 stage 丢弃之和） | 逐轮视图连续性（prefix 稳定性的信息口径表亲） |
| 动机-结果比 | `ρ_t = 存活的 rationale 字符 / 客户端历史 rationale 总字符`（**注入 DEF-107 摘要前**测量） | "见效果不见原因"通道的直接量化 |
| 重读压力 | `r_t = 最近 10 次调用中命中已读句柄的次数`（ledger materials 供给） | 信念偏差的行为症状（RereadDetector 逻辑的计数化，非仅干预） |
| 动作多样性 | `H_a = 归一化 bigram 熵（最近 N=20 次工具调用序列）` | **双端**：`<0.15` → 循环坍缩（已有检测覆盖）；`>0.85 ∧ r_t 高` → 游走（新增检测） |

阈值全部标注"初版猜测，Phase 0/2 用生产数据校准"。

#### Tier 1：logprobs 探针（云端 OpenAI 兼容路径可用时）

`H_BE = mean(−log2 P(y_t | y_<t, V, q))`（响应 token 平均熵）。约束：raw token 熵混杂语言熵与信念熵，只作趋势量使用（见 §7 校准警告）。

#### Tier 2：自一致性探针（主推，provider 无关）

K=3 次独立采样（T=0.7，各 ≤120 token），答案规范化（小写、抽路径、行切分）后聚类，计算类分布熵。成本：~450 token/探针（DeepSeek 价 <¥0.004），并行采样延迟 ≈ 1 RTT。**对 coding agent 的半抽取式问题，一致性比 token 熵更稳健且可移植**——这是与 MMPO（需要可微奖励）不同的选型：我们只需要健康信号，不需要梯度。

#### 对账式信念审计（Tier 2 增强，核心算法）

```
锚定问题（固定模板，确定性）：
  Q1 任务：当前用户任务目标是什么？          → 对账源：最近用户消息 / 台账 head
  Q2 进展：列出已读取/修改过的关键文件        → 对账源：台账 materials
  Q3 下一步：下一步最需要什么信息/动作？      → 无 ground truth，仅一致性熵

D_ledger(Q2) = 1 − recall( extract(答案中的路径集合), 台账句柄集合 )
h_t 分量上报：{D_ledger, 一致性熵(各Q), Tier-0 组合}   ← 分量分开上报，不合成单一分数（避免过早加权固化）
```

#### 触发与卫生（成本与副作用控制）

- **触发**：仅 ILE 事件 + 每会话配额（默认 ≤8 次/会话、≤1 次/轮）；ILE = 压缩 drop 超阈 ∨ fifo 实际丢轮 ∨ epoch 折叠轮。
- **侧路卫生**：探针请求不进 canonical、不写台账 action、不占本地并发槽（**云端 only 起步**，走 logprobs/采样可用提供商）；prompt 复用会话冻结前缀以近零 prefill（append-only 与 hybrid 精确匹配的既有协同）。
- **降级链**：logprobs 可用 → Tier 1；仅采样可用 → Tier 2；云端不可用 → 仅 Tier 0。

### 4.2 逐轮因果账本（信用分配的数据面）

`logs/diag/sessions.jsonl` per-turn 记录增补：

```json
{
  "ifc": {
    "ile": true, "ile_kinds": ["fifo_drop", "compress_drop"],
    "loss_by_stage": {"compress": 12000, "trunc": 3000},
    "tier0": {"retention": 0.71, "rationale_ratio": 0.33, "reread_pressure": 3, "action_div": 0.88},
    "probe": {"method": "consistency_k3", "d_ledger": 0.25, "h_consistency": 1.42, "age_turns": 0}
  }
}
```

视图哈希复用 stage 16（MessageHashDebug）。离线侧 `trace_query.py` 增加 `ifc` 维度：H_BE/D_ledger 斜率 × 失败事件（loop 干预、reread 高发、413、客户端弃用）相关性 = MMPO `ΔH_BE~精度 r=−0.684` 的本系统版验证。

### 4.3 门控执行器（Phase 3，先 shadow）

**(a) epoch 门**：`maybe_epoch` 提交折叠前取信号 `s`（最新探针 ≤2 轮内新鲜度 + Tier-0 组合）：
- `s` 劣化超软阈 → 选既有 `halve=True` 分支（半收编而非全窗口折叠）；
- `s` 劣化超硬阈 → 本轮跳过折叠（defer，接受更高 token 直到既有 413 硬上限兜底不变）。

**只给既有回退阶梯加输入，不新建控制路径。**

**(b) 压缩回退**：BM25 drop 分支完成后，若本轮 `rationale_ratio` 掉出下界 → 触发既有 0.45 封顶分支（结构化截断封顶已是现存机制，缺的只是触发信号）。

**(c) 信息钉（品种补全：第一个保真方向执行器）**：
- **来源**（确定性抽取，无 LLM）：首任务陈述（首轮用户消息核心句）、最新目标（最近用户消息）、近窗口错误签名（tool_result 中 ERROR/异常行）、被截断轮的决策记录（含 tool_use 的 assistant 文本要点）。
- **执行点**：截断豁免（pinned 轮次不丢，先进摘要块）、压缩豁免（pinned span 绕过 BM25 drop）、折叠存续（pins 进折叠面板头部）。
- **抗积分饱和（anti-windup）**：钉预算 ≤ 上下文 5%；陈旧降级——连续 M 轮未被台账动作引用的钉自动降为普通内容。钉集合无界增长 = 控制器的 windup，必须有泄漏。

### 4.4 双端失败检测（补高熵端）

现有 loop 检测只覆盖低熵端（病态确定性重复）。新增游走检测：

```
W 触发 = action_div > 0.85 ∧ reread_pressure ≥ 3 ∧ 台账连续 M=4 轮无新句柄
执行器 = 再定向注入：由台账合成定向块（任务 + 已做动作行 + 材料清单），
         经既有注入基础设施（record_injection 登记、R13 计量）——台账即再合成原料
```

这闭合了"漫无目的重读"（AGENTS.md §8.4 Wasted call 的深层形态）这个至今无自动响应的扰动。

## 6. 度量指标体系（四层 + 护栏）

### 传感器层（新观测量，Phase 0/1）

| 指标 | 口径 | 来源 |
|---|---|---|
| `d_ledger` | 1−recall（探针路径 vs 台账句柄） | 对账审计 |
| `h_consistency` | K=3 采样答案聚类熵 | Tier-2 探针 |
| `h_token`（可选） | 响应平均 token 熵 | Tier-1 探针 |
| `retention` / `rationale_ratio` / `reread_pressure` / `action_div` | §4.1 公式 | Tier-0 |
| `loss_by_stage` | 每 stage 丢弃字符数 | 账本 |

### 健康层（会话聚合，Phase 2）

会话内 `h` 分量斜率（趋势量优先于绝对量——MMPO 证据：Δ 而非绝对值与结局相关）；ILE 计数与逐次损失量；prefix 稳定率（与 `hit_ratio` 交叉验证：信息连续性与缓存命中应同向）。

### 控制有效性层（Phase 3/4）

门触发率、回退选择率（halve 被选比例）、shadow-真实一致率、游走检测查准/查全（以 loop 事件 + 人工抽检为弱标签）。

### 结果层（最终验证，对标既有运维指标）

长会话存活轮数（首次 loop 干预/OOM/413 前的轮数）；进入 saturation 无衰竭比例；`high_drop_ratio` 通知频次（钉生效应使其下降）；reread 干预频次（游走检测应使其下降）；`hit_ratio` 不回归。

### 护栏预算（每条都必须守住，违反即回滚）

| 护栏 | 预算 |
|---|---|
| 探针延迟 | 云端 p50 ≤ 3s，仅 ILE 触发 |
| 探针 token 增量 | ≤ 会话 token 2% |
| canonical 零污染 | 断言：探针请求不产生 canonical 写、不产生台账 action |
| 并发零争用 | 探针永不占本地槽 / 本地队列 bucket |
| 缓存零回归 | 门空闲（shadow/关闭）时 `hit_ratio` 与基线无统计差异 |
| 钉预算 | ≤ 上下文 5%，超限触发降级 |

## 7. 风险与边界

1. **校准 vs 锐度（熵探针的根本盲区）**：低熵 ≠ 正确信念，模型可能"一致地错"。缓解：`D_ledger`（对账准确性）优先于熵分量作为门控输入；熵仅作 Q3 类无 ground truth 问题的补充与趋势量。
2. **锚定问题效度**（MMPO 综述自认开放问题）：缓解 = 半抽取化 + 台账对账；Phase 2 即效度关卡，不达标止步于度量——**度量本身对运维分析仍有独立价值**（失败归因、会话健康巡检），故 Phase 0/1 投入不存在"全部落空"分支。
3. **logprobs 可用性矩阵**：zhipu（anthropic 协议）✗；rapid-mlx 待 Phase 1 实测定案；DeepSeek / OpenAI 兼容 ✓。降级链保证任一形态下 Tier-0 恒可用。
4. **探针自身扰动**：温度采样与侧路请求理论上可能影响提供商侧配额/预算统计；纳入预算护栏与每会话配额。
5. **过控风险（控制论式收尾）**：任何新闭环都可能引入新的振荡模态（门控→视图变化→探针变化→再门控）。缓解：shadow 先行、门频率上限（每会话折叠 defer 至多 1 次）、所有信号趋势化（斜率）而非逐点触发。

## 8. 与综述开放问题的对应（研究侧注）

综述 §6.3 提出"信念清晰度 = 稳态的信息论表述，与控制论接口未被显式统一"——本设计即这个统一在本系统的一次实例化：**setpoint = 任务信息保真度 F 的趋势平稳，sensor = 分层代理（Tier 0/1/2 + 对账），actuator = 门控与钉，internal model = canonical + 台账**。若 Phase 2 验证通过，本仓库将拥有该研究方向的第一个生产级推理时（非训练时）验证载体。

## 9. 动态决策能力边界与扩展层（Phase 5 预案）

**"能否支持动态决策"需分两层回答**：

**层 1：调节级动态决策（事件触发的闭环分支选择）——Phase 3/4 交付，达到。** 判据是决策论五要素齐备：可观测状态（信号）→ 决策规则（阈值/阶梯）→ 执行器 → 决策效果反馈（§6 指标）→ 失效安全默认（信号缺失/过期 → 维持现状）。终态决策点：

| 决策点 | 触发时机 | 动作空间 | 信号（新鲜度） | 失效回退 |
|---|---|---|---|---|
| epoch 折叠 | ILE（折叠轮） | {全收编, 半收编, defer} | 探针+Tier-0（≤2 轮） | 既有阶梯行为 |
| 压缩封顶 | ILE（压缩 drop） | {默认, 触发 0.45 封顶} | Tier-0（当轮） | 默认压缩 |
| 钉集合维护 | 每轮 | {晋升, 降级} | 台账引用（当轮） | 无钉 |
| 游走干预 | 每轮评估 | {再定向注入, 不动} | Tier-0 组合（当轮） | 不动 |

**层 2：策略级动态决策（会话中途切换压缩策略/路由/参数）——信号与层级已预留，接线不在 Phase 0-4 内。** 这是刻意的：策略级动作空间大、过控风险高，必须先有层 1 的效度证据。补齐路径（Phase 5 预案，估 1-2 天）：

1. **代码先例已存在**：`loop_detection.py` 的 `_effective_session_tier` / `_effective_loop_threshold` 就是"按会话状态动态调参"的现成模式；IFC 健康趋势（斜率）作为第二输入维度接入同类 per-session effective 值机制，即可实现会话级压缩参数动态覆盖（如健康恶化 → 该会话 effective profile 降档），无需新机制。
2. **SmartRouter 输入**：`ctx_health` 趋势作为路由因子（衰竭长会话 → 云端大上下文候选），归因经 `X-Proxy-Route-Reason` 暴露。
3. **防振荡约束**：策略切换粒度与会话级斜率挂钩，每会话至多 N 次切换 + 冷却期。

**三个明确的能力边界**（不是缺陷，是显式设计选择）：

- **滞后动态而非即时动态**：探针事件触发，门控信号新鲜度 ≤2 轮，过期退化为 Tier-0。逐请求同步探针 +2~3s 延迟，仅在折叠轮（本就慢）可容忍——若 Phase 3 效果好，可升级为折叠轮同步探针。
- **封闭动作空间**：决策在既有分支集合内选择，不生成新压缩行为。Ashby 品种约束在动作侧依然存在；Phase 2 验证的是信号效度，动作覆盖率由 shadow 一致率与结果层指标另行验证。
- **无在线阈值学习**：阈值校准依赖 Phase 0/2 数据 + 人；自动化阈值调优（RL-lite）是更远期可选项，受 §7.5 过控风险约束。

**决策质量上限 = Phase 2 验证的信号效度**（|ρ| 或 AUC）。若效度中等（ρ≈0.4-0.5），决策是方向性正确而非逐次正确——设计用失效安全默认补偿：不确定即维持现状，动态决策只在没有证据时缺席、不会在没有证据时作恶。这也是 Phase 2 设为硬关卡的原因：它同时是层 1 和层 2 的共同前提。

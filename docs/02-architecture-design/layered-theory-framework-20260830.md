# 认知架构分层理论：系统知识体系的层级抽象

> **状态**：理论框架（完善中）｜**日期**：2026-08-30
> **来源**：认知策略编排器讨论的深化——从"17 种策略太复杂难以理论化"的困境出发，通过分层抽象解决
> **关联**：[认知策略编排器](cognitive-strategies-orchestrator-design-20260830.md)（策略层）· [IFC](information-fidelity-control-design-20260829.md)（控制层实现）· [PDC](progressive-disclosure-context-serving-design-20260829.md)（工程层实现）· [信息面度量推广](information-metrics-applications-survey-20260830.md)
> **一句话**：分层不是妥协——是把"一个无法证明的复杂系统"变成"五个可以独立验证的子系统"的标准科学工程方法。

---

## 1. 认识论困境与解决路径

### 1.1 困境

我们的系统涉及 5 个学科（信息论/控制论/认知科学/系统工程/应用实践）、17 种策略、多层反馈回路——这是一个**复杂适应系统**，其行为不可能通过还原论分析理解，因为系统本质在于**部件间的交互**。

### 1.2 解决方案：分层抽象

与物理学用"有效理论"、计算机科学用"抽象层级"、生物学用"组织层级"解决复杂性的方法相同——**每层有自己的词汇、定律、度量、工具；层间通过明确定义的接口交互；每层可独立研究而不需理解下层**。

### 1.3 认识论定位

Herbert Simon《人工科学》的区分：

| 类型 | 目标 | 方法 | 判据 |
|---|---|---|---|
| 自然科学 | 发现自然规律（真） | 观察→假说→受控实验→理论 | 预测准确、简洁、普适 |
| **人工科学（我们）** | **设计系统并验证有效性（好）** | 设计→实现→评估→改进 | 有效、可靠、可维护 |

我们不是在发现自然规律，而是在设计系统——这决定了验证标准是工程学的（有效/可靠），不是物理学的（普适/精确）。

## 3. 各层详细定义

### Level 1: 信息层（Information Theory）

| 维度 | 内容 |
|---|---|
| **核心问题** | 什么是可测量的？信息的基本极限是什么？ |
| **词汇** | 熵 H(X), 互信息 I(X;Y), 率失真 R(D), 信道容量 C, 数据处理不等式 |
| **定律** | DPI: I(S;B) ≤ I(S;V) ≤ I(S;H)——后处理不能创造信息；率失真：压缩必有代价 |
| **度量** | H_BE (bits), D_ledger (偏差率), 压缩汇率 (bits/K chars) |
| **数学工具** | Shannon 信息论, 统计学, 概率论 |
| **独立验证** | 数学证明 + 经验测量 |
| **向接口提供** | "这些量可以测量，精度为 σ" |

### Level 2: 控制层（Cybernetics / Control Theory）

| 维度 | 内容 |
|---|---|
| **核心问题** | 何时该改变系统行为？如何设计稳定的反馈回路？ |
| **词汇** | 反馈回路, 设定值, 扰动, 升级/降级触发, 失效安全, 稳定性 |
| **定律** | Good Regulator 定理（好的调节器必须包含系统模型）；Ashby 必要品种（执行器品种 ≥ 扰动品种）；最优停止（何时停止当前策略） |
| **度量** | 升级触发的精确率/召回率, 误升级率, 控制回路响应延迟 |
| **数学工具** | 控制理论, 动力系统, 最优停止理论, 赌博机问题 |
| **独立验证** | 稳定性分析 + 仿真 + 经验对比 |
| **向接口提供** | "这些条件触发这些动作" |

### Level 3: 认知层（Cognitive Science）

| 维度 | 内容 |
|---|---|
| **核心问题** | 智能体应该如何思考？什么策略适用于什么问题？ |
| **词汇** | 思考层级(0反射→1反应→2审思→3反思→4治理), 17种策略, 元认知, 组块化, 双系统 |
| **定律** | 认知负荷限制（性能悬崖）; 双系统理论（System 1/2）; 有限理性（满意化）; 组块化（专家压缩） |
| **度量** | H_BE 趋势, D_ledger 准确率, 层级选择正确率, 策略效果对比 |
| **参考理论** | Kahneman 双系统, Anderson ACT-R, Simon 有限理性, Marr 三层分析 |
| **独立验证** | 行为实验 + 消融研究 + 跨任务对比 |
| **向接口提供** | "这个策略需要这些工具" |

### Level 4: 工程层（Systems Engineering）

| 维度 | 内容 |
|---|---|
| **核心问题** | 怎么建？什么基础设施能支撑认知策略？ |
| **词汇** | harness, manifest, 探针, 验证器, 编排器, 小步协议, 台账, git |
| **定律（5条最小原理）** | ①无损分解（松耦合任务可分解至子问题输入 ≤ 预算）；②锚充分性（保地址 > 保内容）；③验证优势（机械校验 > 模型自评）；④后治理收敛（自适应参数 > 固定参数） |
| **度量** | manifest 覆盖率, 验证通过率, 钉预算占比, 压缩汇率 |
| **数学工具** | 软件工程, 分布式系统, 数据库设计 |
| **独立验证** | 系统测试 + 覆盖率审计 + 集成测试 |
| **向接口提供** | "这个协议保证这个质量" |

### Level 5: 实践层（Application）

| 维度 | 内容 |
|---|---|
| **核心问题** | 具体任务怎么完成？领域知识如何应用？ |
| **词汇** | wiki 页面, 代码文件, bug 报告, 补丁, 部署 |
| **度量** | 任务 resolved 率, 时间, token 成本, 人工干预次数 |
| **独立验证** | 端到端任务成功率, 用户满意度 |
| **向接口提供** | "这个任务的成功/失败反馈" |

## 4. 层间接口（抽象屏障）

```
Level 1 → 2: "这些量可以测量，精度为 σ"
            信息层不关心测量被用来做什么控制决策

Level 2 → 3: "这些条件触发这些动作"
            控制层不关心动作的认知含义

Level 3 → 4: "这个策略需要这些工具"
            认知层不关心工具的实现细节

Level 4 → 5: "这个协议保证这个质量"
            工程层不关心具体应用领域

Level 5 → 4: "这个任务的成功/失败反馈"
            实践层不关心改进机制的原理
```

**接口设计原则**：
- 每个接口是**单向依赖**（上层依赖下层，不反向）
- 接口定义**稳定**（改下层实现不影响上层使用）
- 跨层调用是**技术债务**（理想状态是零跨层）

## 5. 分层的实践价值

### 5.1 问题定位

遇到问题时先问"这是哪层的问题"：

```
问题: "模型在处理长文件时忘记前面读过的内容"

Level 5: 任务失败——模型忘了（现象）
Level 4: 认知卸载不足——没有 manifest/recall（根因）
Level 3: 策略错误——应该用分治而非全量阅读（策略）
Level 2: 升级未触发——reread_pressure 检测太慢（控制）
Level 1: 信号太弱——事件级效应低于噪声底（测量）

修复从根因层开始：Level 4 建 ctx_recall 是根本解
```

### 5.2 独立改进

每层可以独立改进，不越层：

| 改进 | 层 | 效果 | 不影响 |
|---|---|---|---|
| 更好的探针（B1 精度提升） | Level 1 | 控制层信号更准 | 不改变控制逻辑 |
| 调整升级阈值 | Level 2 | 减少误升级 | 不改变认知策略 |
| 换类比策略为分治 | Level 3 | 更适合该任务 | 不改变工具实现 |
| 上线 ctx_recall | Level 4 | 信息可恢复 | 不改变任务定义 |
| 换更简单的任务集 | Level 5 | 立刻见效 | 不改进系统能力 |

### 5.3 验证方法分层

| 层 | 验证方法 | 我们的现状 |
|---|---|---|
| 信息层 | 数学证明 | DPI 已证；压缩汇率为经验测量 |
| 控制层 | 稳定性分析 + 仿真 | exp-1/exp-2 经验数据 |
| 认知层 | 行为实验 + 消融 | exp-1 测了 H_BE；策略消融待做 |
| 工程层 | 系统测试 + 审计 | manifest 100%; B1 信度 0.995 |
| 实践层 | 端到端成功率 | exp-1 resolved 率; exp-2 进行中 |

## 6. 17 种策略的分层归属

| 策略 | 归属层 | 层内角色 |
|---|---|---|
| 分类 | **认知层** | 策略选择的前置判断 |
| 模式识别（单次） | **认知层** | 层 0 反射的机制 |
| 尝试 | **工程层** | patch-verify-commit 循环 |
| 分治 | **认知层→工程层** | 认知层决策分解；工程层执行 |
| 抽象 | **认知层** | 层级切换的机制 |
| 类比推理 | **认知层** | 策略之一（需案例库支撑） |
| 间隔重复 | **工程层** | 后台调度器（模型无时间概念） |
| 精细编码 | **工程层** | 入库时自动关联 |
| 双重编码 | **工程层** | 多模态工具 |
| 元认知 | **跨层 1-3** | 信息层测量→控制层触发→认知层反思 |
| 程序化 | **工程层→训练层** | RL 后训练 |
| 认知卸载 | **工程层** | manifest/git/台账基础设施 |
| 孵化 | **控制层** | 暂搁队列管理 |
| 手段-目的 | **认知层** | 前向+后向推理策略 |
| 反事实 | **认知层** | 复盘推理策略 |
| 自我解释 | **认知层** | CoT/探针机制 |
| 交叉练习 | **控制层** | 任务队列调度策略 |

**分布**：认知层 8 种 / 工程层 6 种 / 控制层 2 种 / 跨层 1 种——认知策略最多但工程支撑最关键。

## 7. 5 条最小原理的分层归属

| 原理 | 归属层 | 层内地位 | 验证状态 |
|---|---|---|---|
| 可测升级 | **控制层** | 核心原理 | 🟡 部分验证（H_BE 轨迹级 r=0.26） |
| 无损分解 | **工程层** | 核心原理 | ✅ 实践已验证，缺正式实验 |
| 锚充分性 | **工程层** | 核心原理 | 🟡 机制已验证，效果待测 |
| 验证优势 | **工程层** | 核心原理 | ✅ 已验证（B1 信度 0.995） |
| 后治理收敛 | **工程层** | 核心原理 | 🟡 简单版已验证，完整版待建 |

**关键发现**：5 条原理中 4 条在工程层——**当前系统的瓶颈在工程实现，不在理论**。理论已经够了，需要的是把理论变成代码。

## 8. 与经典分层架构的对照

| 架构 | 层数 | 与我们的对应 | 关键差异 |
|---|---|---|---|
| **Marr 三层**（认知科学） | 3 | 计算层≈L1-2, 算法层≈L3, 实现层≈L4-5 | Marr 太粗，无法指导工程 |
| **OSI 七层**（网络） | 7 | 应用≈L5, 会话/传输≈L3-4, 网络/物理≈L1-2 | OSI 是水平分层，我们是垂直（抽象层级） |
| **计算机栈** | ~6 | 硬件→OS→语言→框架→应用 ≈ L1→L5 | 最成熟的分层先例 |
| **生物学组织层级** | ~6 | 分子→细胞→组织→器官→个体≈L1→L5 | 自然系统的分层（涌现） |
| **Beer VSM** | 5 | System 1-5 ≈ L5-L1 | 最接近的管理控制论映射 |

## 9. 理论提炼路径

```
Level 0: 工程实践（当前状态）
         "这个方法在我的系统上有效"

Level 1: 经验原理（5 条最小原理）     ← 当前可达成
         "在条件 X 下，方法 Y 产生效果 Z"
         可证伪、可重复、有边界条件

Level 2: 中层理论（需要更多数据）
         "对松耦合任务，无损分解+机械验证+锚充分
          的组合优于单上下文方法"
         需 exp-2 code 族 + 更多批次

Level 3: 大统一理论（不要试图建立）
         "认知的一般理论"
         ← 目前不可达，也不必要
```

**行动原则**：聚焦 Level 0→1 的过渡（把 5 条原理写成正式假说，逐条验证），接受"工程学"定位。不做 Simon 说的"不完备的大理论"。

## 10. 总结

| 问题 | 答案 |
|---|---|
| "系统太复杂难以理论化" | 分层——每层独立验证 |
| "各领域概念交叉" | 每个概念归属唯一层 |
| "不知道该改进哪里" | 先定位层，改进不越层 |
| "怎么验证" | 每层有自己的验证方法 |
| "理论提炼到什么程度" | 5 条经验原理（Level 1），不做大统一理论（Level 3） |

**分层是标准科学工程方法**——物理学、计算机科学、生物学都走了这条路。我们做的不是新的，我们做的是**把这条路走到 LLM agent 这个新领域**。

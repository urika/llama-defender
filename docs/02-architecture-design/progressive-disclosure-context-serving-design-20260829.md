# 渐进披露上下文服务（PDC）设计：从"上下文编辑器"到"上下文服务器"

> **状态**：设计提案（未实施）｜**日期**：2026-08-29
> **定位**：IFC（[information-fidelity-control-design-20260829.md](information-fidelity-control-design-20260829.md)）的姊妹篇与建设性补全——IFC 是**防御性**的（"不降级"：门控损失事件、保真度量）；PDC 是**建设性**的（"按需给"：分层披露、模型拉取）。二者合流后，代理从"一次性减法编辑器"升级为"交互式信息服务器"。
> **核心隐喻**：虚拟内存。上下文窗口 = 物理内存（快而有限），台账/档案/客户端历史 = 磁盘（慢而无界），披露清单 = 页表，`ctx_recall` = 缺页处理，信息钉 = 驻留集，预取 = 探针驱动推送，游走 = 抖动（thrashing）。

---

## 0. 命题：当前范式的根本不对称

现有上下文管理（压缩/截断/折叠）全部是**推式单向信道**：代理在请求前一次性猜测相关性（BM25/类型感知），压出固定视图 `V_t`，模型只能接受。被丢弃的信息只能靠环境重观察恢复——昂贵、被 Rapid-MLX 惩罚（Wasted call）、且是循环衰竭的温床。

渐进披露把信道改为**交互式**：代理保证低成本的**可寻址性**（manifest），模型按自身不确定性**拉取**（pull）。信息论依据：速率受限时交互信道优于单向信道——相关性判断从代理（启发式）转移到模型（在环消费者，最清楚自己缺什么）。这正是客户端自身的理念：Claude Code 对**环境**做渐进披露（按需读文件/懒加载工具描述/子代理取细节），PDC 让代理对**会话历史**做同构披露——两层互补，同一原则。

**与 IFC 的分工**：IFC 守住不降级（损失预算分配），PDC 提供恢复与聚焦（按需供给）。Ashby 品种定律在系统层面被满足：调节器（模型）获得对全状态空间的按需访问权。

## 1. 大模型的信息输入需求（披露的目标函数）

好的决策输出依赖四层输入，降级容忍度依次升高：

| 层 | 需求 | 降级容忍 | PDC 对应 |
|---|---|---|---|
| 任务框架 | 目标、约束、当前状态 | **零容忍**（永远驻留） | 信息钉（IFC §4.3，驻留集） |
| 可寻址索引 | "发生过什么、存在什么、在哪"（manifest） | **零容忍**（索引丢失 = 模型不知道自己不知道） | 披露清单（§2 Tier B） |
| 新鲜工作集 | 近窗口轮次、活跃文件原文 | 低容忍 | V_t 主体（现状保留） |
| 尾部内容 | 旧轮次、大工具输出 | **高容忍**（可延后） | 延迟披露（拉取恢复） |

**关键洞见：索引保真 > 内容保真。** DPI 下内容压缩必然损失，但 manifest 是历史的低码率、高互信息编码——每条索引行（handle/轮次/类型/规模）几十 token，保住的是 `I(可寻址性; 历史)`。一次性压缩必须猜对内容；渐进披露只需索引无缺，内容的选择权交给模型。注意力研究同向：干扰项稀释有效信道（lost-in-the-middle），延迟披露同时省预算**并**提高输入信噪比。

## 2. 架构：三层存储 + 一条拉取通道

```
┌─ Hot  V_t（上下文窗口）      任务框架钉 + manifest 行 + 新鲜工作集
├─ Warm 台账/折叠行（代理内存） 动作行、材料索引、钉候选      ← 代理自答，零推理成本
└─ Cold 档案/客户端历史（磁盘） sent_view 全文、原始轮次
                    ▲
        ctx_recall（模型拉取：句柄/轮次/关键词 → 代理检索 Warm→Cold 逐层服务）
        预取推送（探针 Q3 需求信号 / 游走检测触发，IFC 合流点）
```

存储层**已全部存在**（R14 台账、R15 档案、ctx_engine 折叠行），缺的只有查询接口与披露策略。虚拟内存对照：折叠行即页表项，`absorb` 即写回，append-only 即写时复制友好。

### 2.1 三条披露规则

- **R1 索引永不丢**：每个被折叠/截断/丢弃的单元必须留下可寻址索引行（确定性抽取，格式对齐台账 action 行）。manifest 完整性是 PDC 的不变量。
- **R2 内容按需给**：正文进入 `V_t` 只有三条路——钉（驻留）、拉（`ctx_recall`）、推（需求信号预取）。
- **R3 拉取即历史**：每次披露表现为一对 tool_use/tool_result **追加**进历史——append-only 天然兼容、prefix cache 稳定（追加在尾部）、台账可记账、档案可回放。披露不重写任何已有内容，与 canonical 折叠零冲突。

### 2.2 `ctx_recall` 的协议实现（关键工程决策点）

代理注入一个自有工具（定义 ~100 token 常数，走 `tool_filter` 注入通道，双协议端点同构）。模型发起调用后，两种服务方式：

| 方案 | 机制 | 代价 | 依据 |
|---|---|---|---|
| **A：次请求改写**（先行） | 客户端对未知工具回 error result，代理在**下一请求**将该 tool_result 改写为真实检索结果（管线既有能力——`compress_tool_result` 每请求都在改写 tool_result，直接先例） | 模型多等一轮；首答可能含"工具不存在"困惑 | 改动最小，复用压缩改写路径 |
| **B：微轮重派**（升级） | 代理拦截 ctx_recall，**同一请求内**自答并追加结果后重新分发（子代理模式内置化） | 该轮 TTFT +1 次增量 prefill（共享前缀，append-only 保证增量小）；本地模式占用并发槽至微轮结束 | 语义干净，客户端全透明 |

先 A 后 B：A 验证需求与拉取模式，B 解决体验。两者共享检索核心，切换只是接线。

## 3. 与 IFC 的闭环合流（设计的完整故事）

1. **探针 = 需求传感器**：IFC 锚定问题 Q3（"下一步最需要什么信息？"）的答案就是披露需求信号——预取推送的输入。健康度量与披露调度是同一探针的两种用途。
2. **游走检测获得建设性执行器**：高熵游走（IFC §4.4）的最优响应从"再定向注入"升级为"服务拉取/预取所盘旋区域"——直接供给他正试图靠环境重观察恢复的信息。
3. **拉取日志 = 压缩策略的 revealed ground truth**：`拉后即弃率`（拉取的内容恰是先前被压缩/截断丢弃的内容）按类别统计，即为推送策略（钉来源、BM25 权重、折叠粒度）的**假阴性 ground truth**——不再猜测相关性，而是观察模型用拉取"投票"。校准环是频率计数（DEF-104 `≥3 次晋升` 同款），无训练、无 RL。
4. **不可逆动作通道获得部分矫正**（IFC §2.2 损失点 2）：披露是会话内可用的再落地（re-grounding）手段——模型行动前可拉回动机与依据，把"见效果不见原因"部分复原为"可查原因"。

PDC 不依赖 IFC Phase 2 效度关卡：它是加接口而非依信号动作——**模型自己决定何时用**，不确定性由在环消费者消化，风险面小于门控。因此 D 轨道可与 IFC Phase 0-2 并行先行。

## 4. 落地计划（D 轨道，与 IFC Phase 并行）

| Phase | 内容 | 改动文件 | 配置（默认） | 退出准则 |
|---|---|---|---|---|
| **D0**（1-2 天） | manifest 完整性：折叠/截断/压缩全部留索引行（非 epoch 路径补齐）；Tier-0 增"索引覆盖率"指标 | `truncation.py`、`content_compressor.py`、`context_engine.py`、`diagnostics.py` | `PROXY_PD_ENABLED=true`（仅索引，零行为变化） | 抽检：任意被丢弃单元可从 manifest 行唯一定位 |
| **D1**（2-3 天） | `ctx_recall` 注入 + 方案 A 自答（Warm→Cold 逐层检索）；拉取全量计量入账本 | `tool_filter.py`（注入）、`pipeline.py`（改写挂载）、`session_ledger.py`（记账）、新 `ctx_recall.py`（stdlib only） | `PROXY_PD_RECALL_ENABLED=false` | integration：注入/改写/记账链路；snapshot 更新 |
| **D2**（数据期 ≥1 周） | pull log 分析：拉取类别分布、拉后即弃率 → 钉来源与 BM25 权重校准（频率计数闭环） | `tools/trace_query.py` | 无 | 产出校准报告（`docs/04-analysis-diagnostics/`） |
| **D3**（2 天） | 方案 B 微轮重派；探针 Q3 预取 + 游走联动（与 IFC Phase 3/4 合流） | `pipeline.py`、`belief_probe.py` | `PROXY_PD_PREFETCH_ENABLED=false` | 微轮延迟预算内（增量 prefill p50 ≤ 1s）；护栏全绿 |

回滚：各 Phase 独立开关，reload 关闭即回到纯推送范式。

## 5. 度量指标

| 类 | 指标 | 说明 |
|---|---|---|
| 需求侧 | pull 率/会话、类别分布、命中层（Warm/Cold） | 模型真实信息需求的显影——首个直接观测量 |
| 压缩校准 | **拉后即弃率**（分类别） | 推送策略假阴性的 ground truth；驱动钉/权重自校准 |
| 环境侧 | 环境重读率、Wasted call 频次 | 披露应显著降低环境重观察（预期最大行为变化） |
| 信念侧 | `D_ledger` / `H_BE` 趋势（联合 IFC） | 披露 → 信念校准 → 决策质量的最终链条验证 |
| 输入质量 | `V_t` 干扰比（被延迟的尾部 token 占比） | 信噪比代理 |
| 护栏 | pull 结果体积上限（默认 2K chars）、每会话 pull 配额（默认 16）、工具定义开销（~100 tok 常数）、微轮增量延迟 p50 ≤ 1s | 违反即回滚 |

## 6. 风险与边界

1. **欠拉**（模型不知道自己不知道）：manifest 不全是根因——R1 不变量是防线；IFC push 信号兜底。模型校准差的场景由游走检测→预取覆盖。
2. **过拉**（拉取洪泛回填上下文）：体积上限 + 会话配额 + 拉取结果经既有压缩管线（拉取内容同样可被 TS-4 压缩——服务与压缩正交）。
3. **改写风险**（方案 A）：tool_result 改写有快照与回归测试覆盖要求（`compress_tool_result` 先例的测试模式可复制）；OpenAI 协议端点同注入需双协议用例。
4. **与客户端工具的界**：`ctx_recall` 只服务**历史**检索，不越界代理环境工具（读文件仍走客户端）——披露边界即"代理所见过的一切"，恰是 R15 档案的边界，无越权。

## 7. 研究侧注

MMPO 综述的三条"不丢信息"路线（RL 工作流/约束保留/自我总结）之外，PDC 是**第四条路线：交互式披露**——系统工程的原生解法（数据库、操作系统、CDN 对无界数据的共同答案）。综述 §6.4 问"跨路线组合能否更鲁棒"：IFC（路线 B 的度量化）+ PDC（路线 D）+ 台账对账（ground truth 化）即是一次组合实验，且在推理时完成、无需训练。

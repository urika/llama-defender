# 认知策略编排器：人类思维→Agent 系统设计的完整映射

> **状态**：设计研究记录（概念框架，未实施）｜**日期**：2026-08-30
> **来源**：exp-2 code 批跑窗口期间的概念推演 + 认知科学/agent 设计调研
> **关联**：[PDC](progressive-disclosure-context-serving-design-20260829.md)（认知卸载层的工程化）· [IFC](information-fidelity-control-design-20260829.md)（元认知层的工程化）· [信息面度量推广](information-metrics-applications-survey-20260830.md) · [本地栈与训练](local-stack-and-training-feasibility-20260830.md)
> **一句话**：人类从不把 500 页塞进工作记忆——他们用分类、模式、分治、抽象、类比等 17 种策略绕过有限注意力。我们建的 PDC/IFC/harness 本质上是在工程化其中几种。本文记录全部策略的映射、已有实现、前沿与空白，并提出统一它们的"认知策略编排器"架构。

---

## 0. 起点洞察

**Herbert Simon 的有限理性 → LLM 的有限注意力**：人类不是因为注意力有限而"退而求其次"用认知策略——**这些策略本身就是智能的核心**。大模型的 1M 上下文反而是不自然的（没有人这样思考）；让小模型用人类的认知策略工作，才是正确的方向。

exp-2 的死亡螺旋（734 次重复读取）恰好是"人工顺行性遗忘症"的模型——如同电影《记忆碎片》的主角，不是能力不足，是没有外置记忆系统。

## 1. 五个核心策略的 Agent 设计形态

### ① 分类（Categorization）

| 维度 | 内容 |
|---|---|
| 人类机制 | 将新事物归入已知类别，用类别级知识做决策 |
| 认知科学 | 概念形成、原型理论(Rosch)、分类学习 |
| Agent 设计 | **操作类型系统**——harness 维护操作类别（对账/修复/重构/搜索），每类有独立的输入格式、验证规则、路由策略、预算上限 |
| 我们的实现 | 双轴准入四象限（H_BE × D_ledger → 本地/分解/云端/人工）本质上就是分类 |
| 设计机会 | 操作类型系统——每类有独立验证规则/预算/回退策略，新任务先分类再执行 |

### ② 模式（Pattern Recognition）

| 维度 | 内容 |
|---|---|
| 人类机制 | 象棋大师看到棋盘不是 32 个棋子而是 5-6 个模式（Chase & Simon, 1973） |
| 认知科学 | 组块化(chunking)、专长研究(expertise)、自动性(automaticity) |
| Agent 设计 | **技能库/程序性记忆**——成功轨迹编译为可复用技能 |
| 我们的实现 | 拉后即弃→权重晋升（频率计数发现"什么该保留"） |
| 关键洞察 | **模式不是"记住更多"，是"压缩得更少"**——专家的组块是新手看不到的高阶结构 |
| 设计机会 | 模式发现→自动生成新操作类型（元学习） |

### ③ 尝试（Trial and Error / 生成-测试）

| 维度 | 内容 |
|---|---|
| 人类机制 | 爱迪生式试错——生成假设→实验→观察→修正循环 |
| 认知科学 | 生成-测试启发式、强化学习、探索-利用权衡 |
| Agent 设计 | **REPL 循环 / patch-verify-commit 循环** |
| 我们的实现 | harness 核心循环（产出 patch → 机械验证 → git commit / 失败丢弃） |
| 防退化 | 必须有证据存活保障——否则 trial 变成死循环（exp-2 的 734x Read） |
| 设计机会 | 假设树——保留失败分支供回溯（而非丢弃），支持"如果不是这样…"的分支推理 |

### ④ 分治（Divide and Conquer）

| 维度 | 内容 |
|---|---|
| 人类机制 | Simon 的有限理性→满意化→分而治之 |
| 认知科学 | 手段-目的分析、层级规划、子目标分解 |
| Agent 设计 | **任务分解器 + 双判据递归**——分解到"输入集 ≤ 预算 ∧ 探针熵 ≤ 阈值" |
| 我们的实现 | harness 的容量判据（操作级 V=H）+ 熵判据（模型读得懂） |
| 边界条件 | 子问题互信息低（松耦合）时分治最优；紧耦合时退化为长上下文需求 |
| 设计机会 | **耦合度评估器**——分解前测子问题互信息（引用图连通性/依赖分析） |

### ⑤ 抽象（Abstraction）

| 维度 | 内容 |
|---|---|
| 人类机制 | 从具体实例提炼可泛化规则；在抽象层级间自由切换 |
| 认知科学 | 图式理论(Schema)、归纳推理、类比抽象(Gentner) |
| Agent 设计 | wiki 综述页 = 抽象层，source 页 = 具体层；上下行导航 = 抽象↔具体切换 |
| 我们的实现 | wiki 系统的 syntheses/sources 双层 + 链接图 |
| 设计机会 | **自动抽象层级管理**——何时上行/下行、层级间一致性维护 |

## 2. 12 个额外策略（调研发现）

### ⑥ 类比推理（Analogical Reasoning）

- **人类**：从过去案例迁移解法（"这个问题像上次那个"）
- **Agent**：案例库 + 相似度检索 + 解法适配（Case-Based Reasoning）
- **研究**：[CBR for LLM Agents 综述](https://arxiv.org/html/2504.06943v2)；[Analogical Prompting](https://www.promptingguide.ai/techniques/analogical)——LLM 自生成相关案例来辅助推理
- **设计机会**：跨会话/跨项目的解法迁移库

### ⑦ 间隔重复（Spaced Repetition）

- **人类**：艾宾浩斯遗忘曲线→最优复习时刻
- **Agent**：记忆条的定期回顾调度——不是永存，是在遗忘前复习
- **研究**：[FSFM 生物启发选择性记忆](https://arxiv.org/html/2604.20300v2)；[用 140 年前的遗忘曲线修 AI 记忆](https://towardsdatascience.com/context-windows-forget-what-matters-i-used-a-140-year-old-psychology-paper-to-fix-ai-memory/)
- **设计机会**：钉的陈旧度检查→复习调度（已设计了 anti-windup 降级，间隔重复是其精确化）

### ⑧ 精细编码（Elaborative Encoding）

- **人类**：新信息与已有知识关联→深度记忆（"这个概念和 X 类似因为…"）
- **Agent**：Zettelkasten 式笔记链接——每个新知识与已有知识显式关联
- **研究**：A-MEM（Agentic Memory）用 Zettelkasten 灵感做动态记忆链接
- **设计机会**：新信息入库时自动建立与已有条目的关联

### ⑨ 双重编码（Dual Coding）

- **人类**：语言+视觉并行通道（Paivio）——图+文字比纯文字记得牢
- **Agent**：多模态推理（文本+图表+代码+UML）
- **研究**：**空白**——尚无"dual coding for agents"专门论文，这是一个研究机会
- **设计机会**：画架构图/流程图作为推理辅助（降低纯文本的认知负荷）

### ⑩ 元认知（Metacognition）

- **人类**："我知道我不知道"（Flavell）；校准自己的置信度
- **Agent**：H_BE 探针（信念清晰度）+ D_ledger 对账（信念准确性）+ 认知负荷监控
- **研究**：[认知负荷框架](https://arxiv.org/abs/2601.20412)——发现 LLM 有与人类工作记忆类似的"性能悬崖"
- **我们的实现**：IFC 双轴度量 = 元认知的工程化

### ⑪ 程序化/自动化（Procedural Memory / Skill Compilation）

- **人类**：骑车不需刻意思考（Anderson ACT-R 的知识编译）
- **Agent**：RL 后训练将成功模式编译为权重
- **研究**：MemAgent、Context-Folding、Cursor self-summarization
- **我们的实现**：规划中的 35B/9B 后训练管线

### ⑫ 认知卸载（Cognitive Offloading）

- **人类**：用纸笔/日历/环境存储（Clark & Chalmers 扩展心智）
- **Agent**：文件系统/git/manifest = 外置心智
- **我们的实现**：PDC（渐进披露）= 认知卸载的完整工程化

### ⑬ 孵化效应（Incubation）

- **人类**：离开问题→无意识处理→顿悟（"睡一觉就好了"）
- **Agent**：多 agent 并行探索 + 结果汇总；或暂时搁置→换角度→回来
- **研究**：Global Workspace Theory 在 agent 中的复兴
- **设计机会**：任务的"暂搁队列"——一段时间后自动重试（可能因其他任务的经验而有了新视角）

### ⑭ 手段-目的分析（Means-Ends Analysis）

- **人类**：前向（从已知推）+ 后向（从目标倒推）结合
- **Agent**：规划器（目标分解→后向）+ 执行器（从当前状态前向推进）
- **我们的实现**：Tongyi DeepResearch 的三段式（CPT→SFT→RL）体现了这种结构

### ⑮ 反事实推理（Counterfactual Reasoning）

- **人类**："如果当时…会怎样？"——从假设中学习
- **Agent**：模拟分支 / what-if 分析 / 失败复盘
- **设计机会**：实验结束后自动生成反事实分析（"如果 keep=24 而非 12，那个任务会成功吗？"）

### ⑯ 自我解释（Self-Explanation）

- **人类**：向别人解释 = 加深自己理解（Feynman 技巧）
- **Agent**：输出结构化推理过程→自我验证（Chain-of-Thought 及其后继）
- **我们的实现**：探针本质上就是让模型"自我解释"当前状态

### ⑰ 交叉练习（Interleaving）

- **人类**：混合不同题型练习→比顺序练习迁移更好
- **Agent**：多任务训练 / experience replay（RL 已在用）
- **设计机会**：harness 的任务队列按类型交错排列（防止过拟合到单一模式）

## 3. 统一底层：认知负荷理论

[2026 年研究](https://arxiv.org/abs/2601.20412)发现 LLM agent 存在与人类工作记忆类似的**性能悬崖**（performance cliff）——当认知负荷超过阈值时性能突然崩溃。这与 exp-2 死亡螺旋完全一致。

```
认知负荷 = 内在负荷(任务复杂度) + 外在负荷(上下文噪声) + 相关负荷(推理开销)

Agent 设计的负荷管理:
┌─────────────────────────────────────────────────────────────┐
│ 内在负荷 → 分治(④)降低: 每步只处理一个子问题                 │
│ 外在负荷 → 分类(①)过滤: 只加载相关上下文(PDC)                │
│ 相关负荷 → 模式(②)减少: 已知模式不需重新推理(技能库)          │
│ 总负荷   → 抽象(⑤)压缩: 高阶表征降低所有分量                 │
│ 元认知   → 监控: H_BE/D_ledger 实时测量"是否超载"             │
└─────────────────────────────────────────────────────────────┘
```

[认知负荷研究](https://arxiv.org/html/2509.19517v1)进一步区分：**无关上下文（外在负荷）对性能的伤害与任务复杂度（内在负荷）一样大**——精确解释了"大而杂的上下文比小而准的更差"。

## 5. 统一架构：认知策略编排器（Meta-Cognitive Orchestrator）

把 17 种策略统一到一个元系统：

```
认知策略编排器 (Meta-Cognitive Orchestrator)
├── 分类器:     新任务 → 操作类型 → 路由决策
├── 分解器:     大任务 → 子任务队列(容量判据 + 熵判据 + 耦合度判据)
├── 模式库:     成功轨迹 → 技能(自动编译/检索/复用)
├── 案例库:     过去问题+解法 → 类比检索(跨项目迁移)
├── 元认知:     H_BE + D_ledger + 认知负荷 → 实时仪表盘
├── 回顾器:     间隔重复调度 → 定期验证/更新持久记忆
├── 抽象管理器: 层级导航(具体↔抽象) + 层级间一致性维护
└── 假设管理器: 分支推理(保留失败路径) + 反事实复盘
```

**关键设计原则**：这不是 17 个独立工具的堆砌，是一个**闭环**：

```
分类路由 → 分治执行 → 模式发现 → 类比迁移 → 元认知监控
    ↑                                                    ↓
    └──── 抽象提升 ← 回顾维护 ← 假设复盘 ←────────────────┘
```

**我们的已有组件嵌入位置**：
- IFC（信念度量）= 元认知层
- PDC（渐进披露）= 认知卸载层
- harness 小步协议 = 分治层
- wiki 系统 = 抽象层
- 钉 + 权重晋升 = 模式层
- 台账/manifest = 认知卸载的存储实现

**缺失组件**（优先级排序）：
1. **案例库 + 类比检索**（最高边际收益——跨项目解法迁移）
2. **间隔重复调度**（精确化已有的钉降级机制）
3. **认知负荷仪表盘**（实时预测性能悬崖→提前干预而非事后恢复）
4. **假设树管理**（保留失败分支，支持回溯和反事实）

## 6. 与经典认知架构的对照

| 经典架构 | 核心思想 | 我们的对应 |
|---|---|---|
| **ACT-R** (Anderson) | 陈述性记忆 + 程序性记忆 + 缓冲区(工作记忆) | wiki/git + 技能库 + 上下文窗口 |
| **SOAR** (Newell) | 问题空间搜索 + 组块化 + 子目标 | 任务分解 + 模式发现 + 子任务队列 |
| **Global Workspace** (Baars) | 无意识并行→意识广播→串行处理 | 多 agent 并行→结果汇总→单一执行流 |
| **LIDA** (Franklin) | 感知-认知-行动循环 + 认知周期 | request→pipeline→response 循环 |

## 7. 路线图影响

本框架建议的优先行动（按边际收益排序）：

1. **案例库 MVP**：把 exp-1/exp-2 的任务+解法+结局存为可检索案例库，新任务先查类比
2. **间隔重复精确化**：把钉的 anti-windup 从简单陈旧度升级为艾宾浩斯曲线调度
3. **认知负荷仪表盘**：用 H_BE + 上下文规模 + 任务复杂度实时预测"即将超载"→提前分治
4. **假设树**：harness 保留失败分支（当前是丢弃），支持回溯和反事实复盘

这些可以直接挂到 v0.8 看板。

# 系统行为类测试与评估方法论

- 日期：2026-09-05
- 状态：方法论基线（源自 ctx-case 框架建设与零触发/空 patch 归因实践，2026-09-03 ～ 09-05）
- 适用范围：任何"确定性编排层（代理/管线）× 非确定大模型"的交互行为测试与评估——上下文管理、召回、工具触发、指令遵循、注入遵循等

## 1. 这类行为的三个特性决定测法

| 特性 | 后果 | 对策 |
|---|---|---|
| **失败是静默的**——没有 crash，只有"模型悄悄没用上信息"（空 patch、零召回都是这样发生的） | 传统异常/单测抓不到 | 主动构造探针（合成私有事实 + 封死退路的提问），让静默失败显形 |
| **结果由两层共同决定**——管道断了模型必败；管道通了模型也可能不用 | 单测绿灯 ≠ 系统有效；管道红灯时测行为是浪费 | 机械层与行为层分开测、分开判级；L1 红灯清零前不跑 L2 |
| **自由度不可消除**——模型永远保留"不调用/换措辞/走捷径"的自由 | 精确断言必然脆断 | 自由度全部收走给被测对象（确定性脚本客户端 + 罐头工具结果 + 种子化状态），断言事件和事实、不断言措辞 |

## 2. 分层测试金字塔（按确定性递减、成本递增）

```
L1 机械层   报文契约断言（红绿）                每次提交，<2 分钟
L2 事件层   行为发生性断言（调用事件、计数上限）  行为相关改动时
L3 事实层   金标准探针（合成私有事实闭环问答）    同上，择窗
L4 统计层   通过率 / A-B 差值 / 版本趋势         每周或模型变更
L5 任务层   端到端任务成功率（swe-eval）          按版本
```

- **测试**（L1/L2）回答"机制还在吗"：二值红绿，对契约负责；
- **评估**（L3/L4）回答"用得好不好"：分级量化 + 趋势对比，对能力负责；
- 两者共用同一套探针设施，只换判读方式（红绿 vs 分布）。

## 3. 五个关键技术

### 3.1 可控变量注入

把自由变量变成已知量：**合成事实标记**（`KX-7742` 类，磁盘上不存在）、**种子化诊断状态**（manifest/ledger 直写）、**罐头工具结果**（脚本客户端零自由度）。原则：自由度全部收走，只留被测模型的行为自由——"调不调用"从自由意志变成可观测的分叉点。

### 3.2 断环定位矩阵

把行为链拆成带检查点的环节，每种失败组合映射到唯一断点与下游动作（以召回六环为例）：

```
压缩登记 → 线索可见 → ①模型调用 → ②结果含事实 → ③回答含事实
[管道]     [管道]      └──────── 行为层 ────────┘
```

| ①调用 | ②命中 | ③答对 | 定性 → 下游动作 |
|---|---|---|---|
| ✓ | ✓ | ✓ | 全链路通（金标准达成） |
| ✓ | ✓ | ✗ | 管道通，模型利用失败 → 模型侧 |
| ✓ | ✗ | — | 检索/登记断 → 回 L1 修管道 |
| ✗ | — | — | 触发失败 → A/B 定因（cue/意愿） |
| ✓≥N次 | — | — | churn（止损失效） |
| ✗ | — | ✓ | 幻觉命中（事件仍记 FAIL） |

每红必有下一步，不出现"红了对下一步没信息"。

### 3.3 对照组与负对照

行为特征只在**相对值**上有意义：cue 开/关的调用率差才证明 cue 有用；"不该发生的事"单独设守门断言——误触发 = 0、churn ≤ N、未召回时回答不得含标记（幻觉守门）。守门指标与主指标并列报告。

### 3.4 金标准与代理指标分离

**金标准** = 用户视角的最终成功（回答含事实 / 任务完成）；**代理指标** = 触发率、命中率等诊断量。代理指标改善不等于成功（Goodhart 陷阱：模型可能学会机械调用但不利用结果）——任何代理指标优化必须以金标准复测收尾。

### 3.5 非确定性治理

- `temperature: 0` 压采样漂移（本地引擎仍有残余波动）；
- N 次通过率判级，用**置信区间下限**而非点估计（§4.2）；
- 连续两轮结果波动 → 打 `flaky` 旗降级为观察项；
- 报告绑定**模型指纹**（模型/量化版本），换版必须重测基线。

## 4. 定量评估框架

### 4.1 指标体系：主漏斗 + 守门项 + 开销项

主漏斗（每级一个转化率，定位修复点）：

```
召回机会 M
 → ①触发率   = 发出调用数 / M
 → ②命中率   = 结果含目标事实 / 调用数
 → ③利用率   = 回答含事实 / 命中数
端到端成功率 = ③对应数 / M（金标准）
```

守门项（负指标，并列报告）：误触发率（≤10%）、churn 率（=0%）、幻觉率（≈0%，用**每轮随机**的事实标记防蒙对与上下文泄漏）。

开销项（差分）：额外轮次 / 回填 token / 延迟 RTT——`with − without`。召回率提升 20pp 但每任务多 30K tokens，值不值一起看。

### 4.2 小样本的诚实统计

- **点估计无意义**：N=5 观测 3/5，真实率的 95% Wilson 区间是 [13%, 85%]。判级用**区间下限**；
- **筛选测与确认测分离**：筛选 N=5（只认全红/全绿两个极端，快速排雷）；关键改动确认测 N=25-30（80% 真实率的 CI 收窄至 [64%, 90%]）；
- **A/B 用贝叶斯方向概率**：Beta 分布对比 P(A>B) ≥95% 才下结论，否则报告"方向性信号，建议加样"；
- **方差归因**：同配置 N 次的波动是采样方差，配置间差异才是效应——判级永远比"同配置散布"。

### 4.3 判级线预先写进案例

阈值进案例 JSON（`pass_rate{min}` / `false_trigger{max}`），报告器按 Wilson 下限自动判级（达标 / 观察 / 失败-回管道），避免事后拍脑袋。判级线参考：端到端下限 ≥50% 达标；触发率 <30% 回查管道而非怪模型。

### 4.4 数据源优先复用

行为事件需新采；检索质量（Recall@K/MRR）、上下文质量（retention/prefix_breaks/reread_pressure）、开销（usage/延迟）、生产趋势（metrics/history）——诊断数据面（R13-R16、IFC、PDC）已产出。**评估不到的，往往是没记录的**：诊断数据面建设是定量评估的前置投资。

### 4.5 报告样例（目标形态）

```
== ctx_recall 定量评估 ==
模型指纹: ornith-35B-oQ4e-fixed-mtp   日期: 2026-09-05   N=15
端到端成功率: 12/15 (80%, 95%CI[52%,96%])   判级: 观察（下限未过达标线）
漏斗: 触发 14/15(93%) → 命中 13/14(93%) → 利用 12/13(92%)
守门: 误触发 0/5 ✓   churn 0 ✓   幻觉 0/5 ✓
开销: +1.2 轮/任务, +1.8K tokens, +14s

```

## 5. 两个实证教训（本项目 2026-09 实践）

1. **所有单测绿灯 ≠ 系统有效**：ctx_recall 零触发发生在 1516 条单测全绿的系统上（组装层缺陷：护栏分支误伤注入、engine-on 钩子失效）。机械层与行为层缺一不可，且**组装级测试是两者之间缺失的那层**。
2. **静默失败是主要风险形态**：空 patch 三条件、零触发四环，全部无异常日志。这类系统的测试预算应向"探针构造"倾斜，而不是向"异常覆盖"倾斜。

## 6. 节奏与职责

| 层级 | 触发时机 | 成本 | 判读 |
|---|---|---|---|
| L1 | 每次提交 | <2 min | 红绿 |
| L2/L3 | 行为相关改动 | 20-30 min（择窗） | 事件 + 通过率 |
| L4 确认级 | 关键改动后/重启前 | 25+ min/指标 | CI 下限 |
| L4 基线级 | 模型/量化/关键参数变更 | 全量 | 趋势序列（绑定指纹） |
| L5 | 按版本 | 小时级 | 任务成功率 |

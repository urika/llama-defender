# ctx-case 行为层扩展设计（B-suite：模型在环测试）

- 日期：2026-09-05
- 状态：设计评审中（基线框架见 [ctx-single-step-case-debug-design-20260905.md](ctx-single-step-case-debug-design-20260905.md)，已实现并首轮实测）
- 定位：在确定性单步框架（L1）之上增加行为层（L2/L3），把此前判定"不可测"的环节 C（模型调用意愿）纳入可观测范围

---

## 1. 问题：为什么环节 C 此前不可测，现在可以了

基线框架的 22 个案例验证了召回链路的**机械可行性**（注入→检索→自答→兑现全绿），但链路的**最后一环——模型是否真的调用 ctx_recall**——被划入非目标。零触发分析（案例集附录）已证明 C 环"调用意愿"是四环之一，且它的两个前提（cue 线索、兑现可靠）现在都有案例护航。剩下的问题是纯行为问题：**给模型一根拐棍，它用不用？**

行为不可直接断言（非确定、措辞漂移），但行为留下的**事件**可以断言：

| 行为问题 | 可断言的事件 |
|---|---|
| 模型会不会调 ctx_recall？ | K 轮内出现 `tool_use(name=ctx_recall)` 事件 |
| cue 有没有提升调用率？ | A/B 两组的调用率差（统计量） |
| 调了之后用不用结果？ | 最终回答包含召回内容的事实标记（SECRET-类种子） |
| 空结果会不会止损？ | 空结果后重复调用次数 ≤ N（churn 守门） |
| 会不会误触发？ | 普通编程问题下 0 次 ctx_recall 调用 |

**核心手法：种子内容是合成标记（SECRET-CONTENT-XYZ），磁盘上不存在**——模型要么召回、要么承认不知道、要么幻觉（可各各断言）。这让"召回与否"从自由意志变成可观测的分叉点。

## 2. 架构：确定性脚本客户端 + 真实模型 + 事件断言

```
L1（已有）  测试脚本 ──▶ 代理 ──▶ mock backend      断言：报文级，确定
L2（新增）  脚本客户端 ──▶ 代理 ──▶ 真实后端(35B)    断言：事件级+事实级
            （脚本扮演确定性客户端：执行 Read 等真实工具的
              罐头结果，唯一自由度留给被测模型）
L3（统计）  同一 L2 案例 × N 次 ──▶ 通过率 + 与基线比对
```

- **脚本客户端**：runner 升级为微型 agent 环路——发请求 → 解析响应 → 若模型调用 Read/Grep 等真实工具，回放罐头内容（不碰真实磁盘）→ 继续对话，直至 end_turn 或 K 轮上限。模型的全部行为自由被保留，客户端侧零自由。
- **真实后端**：影子代理照旧（隔离不变），`LLAMA_BASE_URL` 指向真实 rapid-mlx :8081（只读推理，无状态污染；影子代理的引擎 canonical/manifest 仍全隔离）。生产代理 :4000 依然零接触。
- **复用**：种子 manifest、capture、报告、归档全部复用 L1 设施；新增的多轮环路和事件断言以套件类型区分。

## 3. 断言词汇扩展（事件级 + 事实级，禁止文本级）

| 断言键 | 语义 | 确定性来源 |
|---|---|---|
| `model_called_tool{name, within_turns}` | K 轮内出现过该工具调用事件 | 事件有无，与措辞无关 |
| `model_call_count_max{name, n}` | 调用次数上限（churn 守门） | 计数 |
| `model_answer_contains{marker}` | 最终回答含种子事实标记 | 标记是我们种的合成串 |
| `model_answer_not_contains{marker}` | 反向对照：未召回时不得含标记（幻觉守门） | 同上 |
| `pass_rate{min}` | L3：N 次运行通过率下限 | 统计阈值 |

明确禁止：对模型回答做文本级 `text_contains("因为...")` 类断言——那是 promptfoo 的领地且天然脆弱。

## 4. B-suite 案例集草案（v1：5 例）

### 4.1 B-TC01 详细规格：闭环问答探针（金标准案例）

测试"模型能否顺利召回被压缩的上下文"——六环链路（压缩登记→线索可见→模型调用→检索命中→结果回填→答对）中前两环已由 L1 覆盖（TC11/TC19/TC20），本案例覆盖后四环并以**答对**为金标准。

**流程（两轮对话）**：

1. **埋事实 + 真实压缩**（engine-off，pre_trunc 相位）：30 轮历史，第 5 轮 tool_result 埋私有事实（如 `MAX_RETRY_TOKENS = 7742`；幻觉守门变体用每轮随机的 `KX-<rand4>` 标记）→ 二发触发 fifo 裁剪 → L1 断言：manifest 登记行存在、head 含事实。
2. **探针提问**：`"MAX_RETRY_TOKENS 的值是多少？该文件此刻不可读，不要读文件，凭会话记忆回答。"`——"文件不可读"封死理性重读的退路，模型只剩召回 / 承认不知道 / 幻觉三条路，各自可断言。

**断环矩阵**：

| ①调用 | ②结果含事实 | ③回答含事实 | 定性 → 下游动作 |
|---|---|---|---|
| ✓ | ✓ | ✓ | 全链路通（金标准达成） |
| ✓ | ✓ | ✗ | 模型利用失败 |
| ✓ | ✗ | — | 检索/登记断 → 回 L1（TC11 缺口） |
| ✗ | — | — | 触发失败 → B-TC02 A/B 定因 |
| ✓(≥3次) | — | — | churn（B-TC03 交叉） |
| ✗ | — | ✓ | 幻觉命中（事件记 FAIL） |

**三变体（难度递进）**：V1 锚点直查（cue 面板带查询键——照指示办事）；V2 语义查询（只有路径/关键词——现实场景）；V3 分页续读（事实埋在 >2000 chars 截断尾部——`@offset` 护栏交互）。

**统计口径**：每变体 N=5，报告三率（触发率/命中率/答对率），判级用 Wilson 区间下限（§10）；筛选级判"全红/全绿"两个极端。

### 4.2 案例集总表

| ID | 测什么 | 输入要点 | 事件/事实断言 | 跑法 |
|---|---|---|---|---|
| B-TC01 触发+召回金标准（§4.1） | 内容仅存于折叠存储时能否召回并答对 | seed 随机事实 + cue/anchor + 封死重读的探针问 | `model_called_tool(ctx_recall,3)` ∧ `model_answer_contains(<本轮标记>)` | ×3-5 ×3变体 |
| B-TC02 cue A/B | RECALL_CUE 是否提升调用率 | A 组带 cue / B 组去除（需 cue 独立 env 开关，无则先补） | 两组调用率贝叶斯对比 P(A>B) | ×3×2 |
| B-TC03 空结果止损 | 空结果 hint 能否防 churn | 空库会话 + 诱导性提问 | `model_call_count_max(ctx_recall, 2)` | ×3 |

## 5. 非确定性治理

1. **温度**：报文固定 `temperature: 0`，压低采样漂移（本地引擎仍有残余波动）；
2. **N 次通过率**：默认 N=3，案例级 `pass_rate{min}` 判红绿（如 B-TC01 要求 ≥2/3）；N 与阈值进案例 JSON，可调；
3. **事件级优先**：断言只看"调用事件 + 种子标记"，不看措辞；
4. **波动标注**：报告对 N 次结果不一致的案例打 `flaky` 旗，连续两轮 flaky 自动降级为"观察项"而非"回归项"；
5. **与 L1 的关系**：L1 红灯（机械缺陷）必须先清零再跑 L2——模型行为结论只在管道健壮时有意义（TC21b 不修，B-TC01 的兑现环节就是断的）。

## 5A. 定量评估设计（漏斗 + 诚实统计 + 判级）

> 通用方法论见 [system-behavior-testing-methodology-20260905.md](system-behavior-testing-methodology-20260905.md) §4，本节是 B-suite 的落地参数。

**主漏斗**（每级转化率，定位修复点）：

```
召回机会 M
 → ①触发率 = 调用数/M  → ②命中率 = 结果含标记/调用数  → ③利用率 = 回答含标记/命中数
端到端成功率 = 利用数/M（金标准）
```

**守门项**：误触发率 ≤10%、churn=0、幻觉率≈0%（B-TC01 标记每轮随机化防蒙对与上下文泄漏）。

**开销项**（with−without 差分）：额外轮次、回填 tokens、微轮自答 +1 RTT。

**小样本统计规则**：
- 判级用 Wilson 95% 区间**下限**，不用点估计（N=5 观测 3/5 的真实率区间 [13%,85%]，点估计 60% 无意义）；
- 筛选级 N=5 只认全红/全绿；确认级 N=25-30 仅对核心指标（端到端成功率）；
- A/B（B-TC02）用 Beta 方向概率 P(A>B)≥95% 才下结论；
- 同配置 N 次散布是采样方差，判级比散布不比单次。

**判级线**（写进案例 JSON，报告器按区间下限自动判）：

| 指标 | 达标 | 观察 | 失败 |
|---|---|---|---|
| 端到端成功率（CI 下限） | ≥50% | 20-50% | <20%（回管道） |
| 触发率（点估计） | ≥60% | 30-60% | <30%（回 L1 查 cue/注入） |
| 误触发率 | ≤10% | 10-30% | >30% |

**数据源**：漏斗三率 + 守门 = B-suite 新采；检索质量（Recall@K/MRR）= `eval_ctx_recall.py` 离线已有；上下文质量 = IFC/sessions.jsonl 已有；开销 = capture usage 已有。新增采集仅 L2 事件。

**报告目标形态**：

```
== ctx_recall 定量评估 ==
模型指纹: ornith-35B-oQ4e-fixed-mtp  日期: 2026-09-05  N=15
端到端成功率: 12/15 (80%, 95%CI[52%,96%])  判级: 观察
漏斗: 触发 14/15(93%) → 命中 13/14(93%) → 利用 12/13(92%)
守门: 误触发 0/5 ✓  churn 0 ✓  幻觉 0/5 ✓
开销: +1.2 轮/任务, +1.8K tokens, +14s
vs 上版(5/15): Δ+47pp, P(新>旧)=96% → 回归确认
```

**节奏**：筛选级（N=5，20 分钟）随行为相关改动跑；确认级（N=25 核心指标）在修完 L1 红灯、重启生产或切参数前；基线级（全套+指纹归档）在换模型/量化时，历史序列落 `logs/ctx_case/`。

## 6. 成本与窗口

- **单案例**：2-5 轮对话 × ~15s/轮（前缀缓存命中口径）≈ 1-2 分钟；B-suite 全量 5 案例 × 3 次 ≈ **20-30 分钟**；
- **后端窗口**：35B 推理与生产共享 rapid-mlx，须在空闲窗口跑（沿用 swe-eval preflight 习惯：起跑前查队列/在途，冲突即延后）；并发会话期间禁止启动（ctx-engine-gate 的教训：瞬时采样会误判空闲）；
- **节奏定位**：L1 每次提交/改动后跑（<2 分钟），L2/L3 择窗跑（修复验证、周回归）；
- 云端模型不进 B-suite：花钱且引入第二变量（不同模型行为不可比）。

## 7. 与现有测试体系的边界

| 体系 | 覆盖 | B-suite 与之的区别 |
|---|---|---|
| L1 ctx-case（本框架） | 报文级机械契约 | — |
| B-suite（本扩展） | 单场景行为事件 | 种子化 diag 状态 + 多轮环路 + 事件断言 |
| promptfoo | 固定 prompt 的回答内容 | 无多轮工具环、无 diag 种子、文本级断言 |
| swe-eval | 全任务 agentic 成功率 | 任务级、贵、慢；B-suite 是其显微镜前置层 |

## 8. 实现切口（待评审后动工）

1. runner 增加 `--behavioral` 模式：`LLAMA_BASE_URL` 指向 :8081、装配脚本客户端环路（工具罐头执行器 ~50 行）、新增事件断言键；
2. 案例集追加 `suite: "behavioral"` 组（5 例 × N 次）；
3. 报告增加 pass_rate/flaky 字段；
4. 预检：起跑前探测 :8081 空闲（沿用队列/在途判据），非空闲即拒跑；
5. 预算：B-suite 全量预计 +250 行 runner 代码，复用率 >70%。

## 9. 风险与边界

- **红绿语义弱化**：L2/L3 的 FAIL 是"这批没达标"而非"代码错了"——报告须明确区分机械红灯（L1）与行为黄灯（L2/L3），避免误读；
- **模型升级即基线漂移**：后端模型/量化换版后行为基线必须重测（记录模型指纹到报告）；
- **B-TC02 的 A/B 依赖 cue 可独立开关**：需确认 cue 注入路径有 env 级开关（truncation/epoch 两路），若无则先补开关再测——这本身就是个小的可测性改进；
- **不测创造性行为**：B-suite 只收窄到"上下文管理相关行为"（触发/遵循/止损/利用/误触发），不做通用能力评估。

## 3. 测试任务与结果

### 3.1 任务 1：AVL 树实现与运行时验证

**任务描述**：要求模型实现一个完整的 AVL 树，包含 `insert`、`delete`、`search`、`inorder`、`height`、`is_balanced` 方法，并自行处理重复键。

**评估方式**：
- 结构检查：确认代码包含上述关键方法。
- 运行时检查：执行插入、删除、搜索序列，验证排序结果与平衡性。

**结果**：✅ 通过

- 结构检查：8/8
- 运行时验证：通过
- TTFT：1.13s
- 总耗时：15.4s

**结论**：模型能够生成可直接运行的自平衡二叉搜索树代码。

---

### 3.2 任务 2：多约束调度逻辑推理

**任务描述**：五人（Alice、Bob、Carol、Dave、Eve）在周一至周五各讲一天，给出以下约束：

1. Alice 在 Bob 前一天。
2. Carol 在周三。
3. Dave 在 Eve 后一天。
4. Bob 不在周五。
5. Eve 不在周一。

要求输出 JSON 格式的日程安排。

**正确答案**：

```json
{
  "Mon": "Alice",
  "Tue": "Bob",
  "Wed": "Carol",
  "Thu": "Eve",
  "Fri": "Dave"
}
```

**模型输出**：

```json
{
  "Mon": "Eve",
  "Tue": "Alice",
  "Wed": "Carol",
  "Thu": "Bob",
  "Fri": "Dave"
}
```

**结果**：❌ 失败

**失败原因**：模型将 Eve 安排在周一，直接违反约束 5（Eve 不在周一）。其余约束虽然部分满足，但关键约束冲突导致整体错误。

### 3.3 任务 3：并发代码缺陷诊断与修复

**任务描述**：给出一段故意写错的 Python 计数器代码，`with self.lock:` 块为空，实际读改写操作在锁外执行。要求模型识别 bug 并给出修复。

**评估方式**：
- 是否指出锁块为空、读改写在锁外。
- 是否给出将 `self.value += 1` 或等价操作放入锁内的修复。

**结果**：✅ 通过

- 模型准确指出：`with self.lock:` 块为空，`current = self.value; self.value = current + 1` 发生在锁外。
- 给出了正确的修复方案。
- TTFT：1.0s
- 总耗时：5.1s

---

### 3.4 任务 4：复杂结构化 JSON 生成

**任务描述**：生成一个软件项目计划 JSON，满足以下约束：

- 顶层键：`project`、`version`、`tasks`
- `tasks` 必须恰好 3 项
- 每项任务必须包含 `id`（1–3 顺序唯一）、`title`、`priority`（low/medium/high 之一）、`subtasks`（2 个字符串）、`done`
- 恰好一项任务 `priority` 为 `high`，且该项 `done` 为 `false`
- 第一项任务的 `title` 必须包含 `design`

**结果**：✅ 通过

- 模型输出格式正确的 JSON。
- 所有约束均满足。
- TTFT：1.2s
- 总耗时：4.0s

### 3.5 任务 5：长上下文信息提取与聚合

**任务描述**：向模型提供 30 个项目的段落（状态、预算、负责人等信息被打乱顺序），要求只根据文档内容回答三个聚合指标：

- `in_progress_count`：状态为 `in_progress` 的项目数
- `total_budget_completed`：状态为 `completed` 的项目预算总和
- `leads_with_budget_over_200k`：预算超过 20 万美元的负责人集合

**正确答案**：

```json
{
  "in_progress_count": 8,
  "total_budget_completed": 1312500,
  "leads_with_budget_over_200k": ["Alice", "Bob", "Carol", "Dave", "Eve"]
}
```

**模型输出**：

```json
{
  "in_progress_count": 7,
  "total_budget_completed": 1057500,
  "leads_with_budget_over_200k": ["Eve", "Alice", "Bob", "Carol", "Dave"]
}
```

**结果**：❌ 失败

**失败原因**：
- `in_progress_count` 少算了 1 个（实际 8，模型给出 7）。
- `total_budget_completed` 计算错误（实际 1,312,500，模型给出 1,057,500）。
- 负责人集合虽然正确，但说明模型对集合判断没问题，数值聚合存在系统性偏差。

## 5. 观察与建议

### 5.1 优势

- **代码生成能力强**：AVL 树代码结构完整，可直接执行并通过平衡性验证。
- **并发缺陷诊断准确**：能识别空锁块和锁外读改写问题。
- **结构化输出稳定**：复杂 JSON 约束全部满足，格式规范。
- **响应速度可接受**：TTFT 在 1s 左右，代码生成任务约 15s 完成。

### 5.2 劣势

- **精确逻辑推理存在漏洞**：在任务 2 中漏掉了“Eve 不在周一”这一否定约束。
- **长上下文数值聚合不可靠**：任务 5 中模型无法准确完成跨多段落的计数与求和。
- **Token 计数未返回**：本次测试通过流式接口调用，后端未在响应中返回 `usage` 字段，导致无法统计实际输入/输出 token。

### 5.3 后续建议

1. 对需要精确计数的任务，建议让模型显式列出中间步骤（chain-of-thought）后再给出最终答案。
2. 对多约束逻辑题，可尝试使用更低温度（`temperature=0.1`）并重复采样多次取一致结果。
3. 在生产使用中，对长上下文聚合类结果应增加外部校验或让模型分步计算。
4. 若需要 token 使用数据，可改用非流式请求或检查后端是否支持 `stream_options`。
